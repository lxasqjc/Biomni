💡 Why does "machine death" look like a network outage?

When the OOM killer fires, it kills processes ranked by oom_score. On a shared system, this can include sshd child processes handling your current sessions. The SSH connection drops, you can't reconnect, and the machine appears dead — but the hardware is fine. The sister node on the same network remains reachable because it's a separate process domain.

Confirmed by: SSH reconnecting successfully 10–15 min later once OOM pressure subsides naturally.

CLOSE-WAIT Socket Leak in vLLM Keepalive

Fixed · commit 7867e18

Each API server runs a background thread that pings the remote vLLM /models endpoint every 300 seconds to prevent the inference engine from sleeping. A 3-line bug caused every ping to permanently leak a TCP socket.

❌ Before — leaks socket 
# Each ping opens a new TCP connection.
# vLLM sends FIN. Local side never closes.
# Socket stuck in CLOSE-WAIT indefinitely.
resp = _requests.get(
    f"{base_url}/models",
    timeout=10
)
✅ After — closes cleanly 
# Session context manager closes the
# connection pool when the 'with' exits.
# Connection: close tells vLLM to not
# keep-alive from its side either.
with _requests.Session() as s:
    s.headers.update({"Connection": "close"})
    resp = s.get(f"{base_url}/models",
                 timeout=10)
ℹ️
Does this affect experiment scripts? No. The keepalive thread is server-side only — it pings vLLM from the API server process. Your client's HTTP connection to the Biomni API, and the agent's inference calls to vLLM via the OpenAI client, are completely unaffected.

  • biomni_api_server_qwen3_next_80b_auto_clean_azimuth.py

Output Directory Accumulation

Fixed · commit 9d16118

Every Biomni query created a timestamped directory under local_outputs/ — even when running large batch experiments where no one ever looks at the output files.

Opt-in via environment variable

All 5 API servers now read BIOMNI_LOCAL_OUTPUTS at startup. Default is 0 (disabled). Set to 1 to re-enable for interactive/UI sessions where you want to keep intermediate files:

# Disabled (default — for batch experiments)
uvicorn biomni_api_server_qwen3_next_80b_auto_clean_azimuth:app \
  --host 0.0.0.0 --port 8020

# Enabled (for interactive/UI sessions)
BIOMNI_LOCAL_OUTPUTS=1 uvicorn biomni_api_server_qwen3_next_80b_auto_clean_azimuth:app \
  --host 0.0.0.0 --port 8020

If a client requests save_pdf=True, a directory is still created on-demand for that specific PDF — so PDF saving always works regardless of the flag.

One-time cleanup command

# Delete timestamped dirs older than 7 days (keeps named dirs like test_gradio)
find local_outputs/ -mindepth 1 -maxdepth 1 -type d -mtime +7 -name "202[56]*" -print0 \
  | xargs -0 -P8 rm -rf

Named special directories (e.g. test_gradio, deepresearch-discard) are preserved automatically because they don't match the 202[56]* glob pattern.

Biomni API Design — Chat History, Execution Logs & PDF Saving

Reference

The Biomni API and Langflow component expose three key configuration knobs that control how conversation data flows through the system.

1 · use_chat_history — Multi-turn vs. independent queries

Controls whether conversation context is preserved across multiple API calls.

✅ ENABLED — multi-turn conversation

User
What is BRCA1?
Biomni
BRCA1 is a tumour suppressor gene involved in DNA repair…
User
What are common mutations in this gene?
Biomni
Common BRCA1 mutations include 185delAG, 5382insC… ✅ Knows "this gene" = BRCA1

❌ DISABLED — independent queries

User
What is BRCA1?
Biomni
BRCA1 is a tumour suppressor gene…
User
What are common mutations in this gene?
Biomni
Which gene are you referring to? ❌ No context
Use when: ✅ Research dialogues ✅ Exploratory follow-ups ❌ Batch processing ❌ Independent queries

2 · include_execution_log — Transparency for debugging

When enabled, the response includes the full agent execution trace: reasoning steps, tool calls, intermediate results, and self-critique iterations.

include_log = False (default)

BRCA1 is a tumour suppressor gene involved in DNA repair and genome stability.

include_log = True

BRCA1 is a tumour suppressor gene…

[Execution Log]
→ query_pubmed("BRCA1 function")
→ Found 847 papers, top: "BRCA1 in DNA repair" (2023)
→ query_uniprot("BRCA1_HUMAN")
→ Self-critique: sufficient evidence? Yes
Total: 3 tool calls, 4 reasoning steps

Use when: ✅ Debugging agent behaviour ✅ Understanding tool use ❌ Production (adds latency + tokens)

3 · save_pdf — Conversation history export

When True, saves the full conversation (query + agent reasoning + tool calls + answer) as a PDF to local_outputs/<timestamp>/. Note: with BIOMNI_LOCAL_OUTPUTS=0 (the new default), a directory is only created on-demand when save_pdf=True.

# Example API call
POST /chat
{
  "query": "What genes are upregulated in BRCA1-mutant tumours?",
  "save_pdf": true,
  "include_execution_log": false
}
Use when: ✅ Research reports ✅ Audit trail needed ❌ Batch experiments (disk pressure)

Process Isolation — Surviving tmux Crashes

Best practice

API servers and the Gradio UI were originally started inside tmux sessions. When a tmux session died (for any reason — OOM, admin action, network hiccup), all servers died with it. We moved to systemd-run --user --scope for true process isolation.

❌ Fragile — dies with tmux 
nohup uvicorn app:app \
  --port 8020 \
  > logs/server.log 2>&1 &

# Survives terminal disconnect,
# but NOT tmux session kill or
# parent process death (SIGHUP)
✅ Robust — survives everything 
systemd-run --user --scope \
  --unit=biomni-8020 \
  bash -c "exec uvicorn app:app \
    --port 8020 \
    > logs/server.log 2>&1"

# Process owned by systemd user
# slice — survives tmux kill,
# logout, and SSH disconnect

Robust restart pattern (full sequence)

When restarting a port that was already running (e.g., after a code update):

# Step 0: Clear zombie scopes from previous crashed runs
systemctl --user daemon-reload

for port in {8010..8022}; do
  # Step 1: Kill the process instantly (no SIGTERM wait)
  pid=$(lsof -t -i :$port 2>/dev/null)
  [ -n "$pid" ] && kill -9 $pid 2>/dev/null

  # Step 2: Clear the scope if it's in 'failed' state
  systemctl --user reset-failed biomni-$port.scope 2>/dev/null

  # Step 3: Launch fresh in a new scope
  systemd-run --user --scope --unit=biomni-$port \
    bash -c "exec uvicorn app:app --port $port > logs/server_$port.log 2>&1" &
done
⚠️
Why not systemctl stop? It sends SIGTERM and waits up to 90 seconds. If uvicorn is mid-query (e.g. a 3-minute LLM inference), the stop hangs. kill -9 is instant and safe here because each request creates a fresh agent instance.

Checking scope status

# List all running Biomni scopes
systemctl --user list-units "biomni-*.scope"

# Check if a specific port is running
systemctl --user is-active biomni-8020.scope

# View recent logs for a port
journalctl --user -u biomni-8020.scope -n 50 --no-pager
